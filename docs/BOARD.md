# Дошка агентів

Хто з агентів що зараз робить і що вже зроблено.

> **Актуальна версія цієї дошки та всієї теки `docs/` — лише в гілці [`coordination`](#гілка-coordination--спільні-документи).** Копія в `main` оновлюється із запізненням. Перед будь-якою роботою: `python tools/agents/status.py`.

## Гілка `coordination` — спільні документи

**Що де живе:**

| Що | Де змінюється | Як потрапляє далі |
|---|---|---|
| Уся тека `docs/`: діздоки (VISION, MODULES, MATH, CONTRACTS, RESOURCES), задачі (TASKS), дошка (BOARD), пропозиції (PROPOSALS) | гілка **`coordination`**, прямий push без PR | Перун регулярно зливає `coordination` → `main` |
| Код, тести, `contracts/`, `tools/`, `app/`, `AGENTS.md`, `README.md` | гілки задач `<ім'я>/<ID>-…` | PR у `main`, злиття — Перун |

**Перед будь-якою роботою** (початок сесії, нова задача, перед PR):
```bash
git fetch origin
python tools/agents/status.py            # дошка й задачі з origin/coordination, чужі гілки, відставання від main
git show origin/coordination:docs/TASKS.md | less   # або відкрити документ з coordination
```

**Як змінювати документи.** Зручно тримати `coordination` в окремій робочій теці, щоб не перемикати гілку задачі:
```bash
git worktree add ../Nasa-2026-coord coordination   # один раз
cd ../Nasa-2026-coord
git pull --rebase origin coordination              # завжди перед зміною
# … правки в docs/ …
git commit -am "BOARD: Велес бере B3" && git push origin coordination
```
- Лише fast-forward: перед push — `git pull --rebase`; **force push у `coordination` заборонено**.
- Коміт маленький і про одне: заявка, статус, правка одного документа.
- Код у `coordination` не комітимо; `docs/` у гілках задач і PR у `main` не змінюємо — так дві гілки ніколи не конфліктують.
- Змінили API або модуль — код і `contracts/` у PR до `main`, а опис (`MODULES.md`, `CONTRACTS.md`) — окремим комітом у `coordination`.

**Синхронізація (робить Перун):**
- `coordination` → `main`: PR наприкінці кожної хвилі або раз на день;
- `main` → `coordination`: `git merge origin/main` після злиття коду, щоб гілка не відставала.

## Права на документи

| Документ | Хто змінює | Як |
|---|---|---|
| `BOARD.md` | кожен агент | лише свій розділ |
| `TASKS.md` | кожен агент | статус своєї задачі; нову задачу — новим рядком |
| `TASKS.md`: хвилі, доріжки, розподіл | **лише Перун** | — |
| `PROPOSALS.md` | кожен агент | нова пропозиція в кінець за шаблоном; чужі не редагувати |
| `VISION.md`: рішення та журнал рішень | **лише Перун** | агенти пропонують через `PROPOSALS.md` або «Відкриті питання» |
| `VISION.md`: «Відкриті питання» | кожен агент | дописувати |
| `MODULES.md`, `MATH.md`, `CONTRACTS.md`, `RESOURCES.md` | агент, чия задача це змінює | точкові правки в межах задачі; формули в MATH.md — разом із тестом у коді |
| `AGENTS.md`, `README.md` (у `main`) | **лише Перун** | — |

## Правила заявок
1. **Перевірити**, що задачу ніхто не взяв: `python tools/agents/status.py --check <ID>` (дошка в `coordination`, гілки інших агентів і заявки в них).
2. **Заявити одразу, до початку роботи:** у `coordination` — свій розділ «Зараз» і статус 🔄 у TASKS.md, одразу `git push origin coordination`. Потім гілка задачі `<ім'я>/<ID>-<коротко>` від свіжого `main`.
3. **Виконано:** PR з кодом у `main`; у `coordination` — рядок із «Зараз» у свій «Журнал» (ID, назва, PR) і 👀 у TASKS.md. Після злиття Перун ставить ✅.
4. **Відмова від задачі:** прибрати заявку в `coordination` і видалити гілку задачі.
5. Кожен редагує **лише свій розділ** — так зміни дошки від різних агентів не конфліктують.
6. Заявка без комітів понад 24 години вважається покинутою: Перун може її зняти.
