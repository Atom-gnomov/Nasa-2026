# Вимоги до модулів

Документ описує модулі застосунку: за що кожен відповідає, які файли до нього належать, що він приймає й повертає, що потрібно для MVP і що відкладено на другу чергу.
Загальні вимоги — у [VISION.md](VISION.md), джерела даних — у [RESOURCES.md](RESOURCES.md).

**Стек:** Python 3.11+, Flask 3, Jinja2-шаблони, ванільний JavaScript (ES-модулі), Three.js для 3D.
**Запуск:** див. [README.md](../README.md).

Статуси: ⬜ не розпочато · 🟨 каркас / заглушка · ✅ готово для MVP.

У кожного модуля є підрозділ «Пропозиції» — туди дописуємо ідеї та покращення (коротко, з підписом). Великі пропозиції — у [PROPOSALS.md](PROPOSALS.md).

## Карта модулів

```
app/
├── __init__.py, config.py      → М1. Ядро застосунку
├── routes/pages.py, templates/ → М2. Сторінки (вкладки)
├── routes/api.py               → М3. JSON API
├── core/                       → М0. Математичне ядро (чисті функції, без Flask)
├── services/
│   ├── sites.py, data/sites.json        → М4. Каталог місць
│   ├── ephemeris.py                     → М5. Ефемериди
│   ├── horizon.py                       → М6. Радіогоризонт
│   ├── elevation.py                     → М6. Висота, нахил і експозиція (DEM LOLA)
│   ├── metrics.py                       → М7. Метрики
│   ├── timeline.py                      → М7. Ряди й підсумки за період, маска горизонту
│   ├── system.py                        → М13. Стан системи й орбіти
│   ├── temperature.py                   → М18. Температура (LRO Diviner)
│   └── dsn.py, data/dsn_*.json          → М8. Зв'язок і DSN
└── static/js/
    ├── state.js        → М9.  Спільний стан
    ├── calendar.js     → М10. Календар
    ├── overlay.js      → М11. Оверлей метрик
    ├── moon_globe.js, globe_view.js → М12. Глобус Місяця
    ├── system_view.js  → М13. 3D-вид системи
    ├── compare.js      → М14. Порівняння місць (ще не створено)
    └── three/          → М16. 3D-підсистема (спільна для М12 і М13)
tools/                  → М15. Передрозрахунки
Dockerfile, compose.yaml → М17. Docker (ще не створено)
tests/                  → тести для всіх модулів
```

Залежності: `М0 Ядро` → `М5 Ефемериди` + `М6 Радіогоризонт` → `М7 Метрики` → `М3 API` → `М11 Оверлей`, `М14 Порівняння`.
3D: `М16 3D-підсистема` → `М12 Глобус Місяця`, `М13 3D-вид системи`.
**М6 закрито в гілці `moon`:** маска горизонту рахується на льоту з DEM LOLA (20/80 м біля південного полюса, далі — глобальний). Наступне на критичному шляху — злиття `moon` у `main` і М14 Порівняння.
Статуси «✅ (`moon`)» нижче означають: готово й перевірено в гілці `moon`, але ще не злито в `main`.

## М0. Математичне ядро — ✅ (основа)
**Файли:** `app/core/*.py`, тести `tests/test_core_*.py`, `tests/test_ephemeris.py`
**Призначення:** уся математика проєкту в одному місці. Чисті функції на numpy, без Flask — їх можна викликати зі скриптів `tools/`, сервісів і тестів. Формули — [MATH.md](MATH.md).

| Модуль | Що містить | MATH.md |
|---|---|---|
| `constants.py` | радіуси, швидкість світла, сонячна стала, періоди | §0–4 |

| `ephemeris.py` | клас `Ephemeris` (DE440 через skyfield): вектори Сонця/Землі/станцій у системі ME, траєкторії на небі точки, Місяць над станцією, сітки часу | §1–2, §9 |
| `horizon.py` | пониження горизонту, `disk_fraction` (сегмент круга), `HorizonMask`, `compute_mask` з довільної функції висот | §6 |
| `events.py` | `find_crossings` / `next_crossing` — усі сходи й заходи, векторизована бісекція | §7 |
| `stats.py` | години за період, частка часу, найдовша ніч, інтервали | §8 |
| `power.py` | потік Сонця, потужність панелі (вертикальна / горизонтальна) | §10 |
| `thermal.py` | рівноважна температура | §11 |
| `radiation.py` | доза ГКП з урахуванням відкритого неба | §12 |
| `launch.py` | прибавка від обертання Землі, нахил, зміна площини | §13 |
| `scoring.py` | нормалізація, ваги ROC, зважений бал, мін-макс, фронт Парето | §14 |
| `dem.py` | DEM LOLA у форматі PDS3 (.img + .lbl): проста циліндрична й полярна стереографічна проєкції за `dsmap*.cat`, мозаїка «найдетальніший DEM у точці» (`moon`) | §6.2, §6.4 |

- Нова формула → функція в `app/core/` + тест із числом із MATH.md.

**Файли:** `app/services/ephemeris.py`, `tools/download_kernels.py`
**Призначення:** азимут, кут місця та відстань Сонця й Землі з точки на Місяці.

**Інтерфейс:**

- Точність кута місця — не гірше 0,1°.
- Діапазон дат — щонайменше 2026–2060 (десятки років уперед).

## М6. Радіогоризонт — ✅ (`moon`, рельєф LOLA)
**Файли:** `app/services/horizon.py`, `app/services/elevation.py`, `app/core/dem.py`
**Призначення:** чи видно Сонце/Землю з урахуванням рельєфу.
**Математика:** [MATH.md](MATH.md), розділ 6.

**MVP:**
- ✅ `disk_fraction` — точна частка диска (сегмент круга) замість лінійного наближення.
- ✅ `compute_mask(height_fn, …)` — маска з будь-якої функції висот, працює й на полюсі; перевірено на синтетичному рельєфі.
- ✅ (`moon`) `load_mask(lat, lon, height)` — маска з DEM LOLA на льоту (`core/dem.mosaic_height_fn`): у кожній точці променя — найдетальніший продукт (LDEM_875S_20M → LDEM_80S_80M → LDEM_64 → LDEM_16), кеш; без DEM — гладка сфера (`source: flat`). 0,2–0,3 с на точку, тому передрахунок для каталогу не потрібен.
- ✅ (`moon`) `/api/elevation` — висота, нахил і експозиція схилу; `/api/horizon` — маска, відкрите небо, доза ГКП.
- ✅ (`moon`) Звірено: дно Шеклтона — вічна тінь (горизонт 19,8–23,6°, Сонце не сходить за рік), що узгоджено з Diviner (T_max 88 K).

**Друга черга:** маски для довільних точок на льоту, сітки для підбору локацій.

## М16. 3D-підсистема — 🟨

**Інтерфейс (пропозиція):**

## М17. Docker і розгортання — ⬜ (на майбутнє)
**Файли (створити):** `Dockerfile`, `compose.yaml`, `.dockerignore`, розділ у `README.md`
**Призначення:** запуск застосунку однією командою на будь-якій машині (ноутбук команди, сервер для демо, хмара).

**Вимоги:**
- `docker compose up` збирає й запускає сайт на http://localhost:5000; більше нічого встановлювати не потрібно.
- Базовий образ — офіційний `python:3.13-slim` (з закріпленою версією); залежності з `requirements.txt` встановлюються окремим шаром, щоб зміни коду не перевстановлювали бібліотеки.
- Вебсервер у контейнері — **gunicorn**, а не `flask run` (той лише для розробки).
- Ефемериди DE440 (~114 МБ) — усередині образу: застосунок працює без доступу до інтернету.
- Великі дані (DEM LOLA, маски горизонту, `data_cache/`) — у **томі** (volume), шлях задається `LSE_CACHE_DIR`; образ не роздувається, дані не губляться при перезбиранні.
- Налаштування — лише через змінні середовища (`SECRET_KEY`, `LSE_CACHE_DIR`, `LSE_EPHEMERIS_PATH`, порт); секрети не потрапляють в образ і git.
- Контейнер працює не від root; є `HEALTHCHECK` на `/api/health`.
- Скрипти передрозрахунків (`tools/`) запускаються в тому самому образі: `docker compose run --rm app python tools/...`.
- Тести в контейнері: `docker compose run --rm app python -m pytest`.

**Друга черга:**
- збирання образу й прогін тестів у CI (GitHub Actions) на кожен PR;
- публікація образу в GitHub Container Registry;
- окремий сервіс для передрозрахунків, якщо вони стануть довгими.

## М18. Температура поверхні — ✅ (`moon`)
**Файли:** `app/services/temperature.py`, `tools/build_temperature_data.py`, шар «Температура» в `globe_view.js`
**Призначення:** виміряна температура поверхні для вибору місця й теплового режиму апарата.
**Дані:** LRO Diviner з PDS (`lro_diviner_derived1`): GCP — 0,5°, бін місцевого часу 15 хв, 2009–2015 (Williams et al. 2017); PRP південь — 0,5 км, річні середня й максимум, глибина стабільного льоду (Paige et al. 2010).

**Інтерфейс:** `/api/temperature?lat&lon&datetime` (на дату, добова крива, мін/макс/середня, PRP), `/api/temperature/map?kind&datetime` (коди 0…255 для шейдера).

**Обмеження:** «на дату» — середнє вимірювань для місцевого часу, сезони не розділено (біля полюсів суттєво); PRP — модель теплового балансу, узгоджена з Diviner, лише в колі 300 км навколо полюса; код льоду −1 (не описаний у мітці) трактуємо як «стабільний на поверхні» (див. MATH.md §11.1).
