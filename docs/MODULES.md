# Вимоги до модулів

Документ описує модулі застосунку: за що кожен відповідає, які файли до нього належать, що він приймає й повертає, що потрібно для MVP і що відкладено на другу чергу.
Загальні вимоги — у [VISION.md](VISION.md), джерела даних — у [RESOURCES.md](RESOURCES.md).

**Стек:** Python 3.11+, Flask 3, Jinja2-шаблони, ванільний JavaScript (ES-модулі), Three.js для 3D.
**Запуск:** див. [README.md](../README.md).

Статуси: ⬜ не розпочато · 🟨 каркас / заглушка · ✅ готово для MVP.

У кожного модуля є підрозділ «Пропозиції» — туди дописуємо ідеї та покращення (коротко, з підписом). Великі пропозиції — у [PROPOSALS.md](PROPOSALS.md).

## Карта модулів

```
app/
├── __init__.py, config.py      → М1. Ядро застосунку
├── routes/pages.py, templates/ → М2. Сторінки (вкладки)
├── routes/api.py               → М3. JSON API
├── services/
│   ├── sites.py, data/sites.json        → М4. Каталог місць
│   ├── ephemeris.py                     → М5. Ефемериди
│   ├── horizon.py                       → М6. Радіогоризонт
│   ├── metrics.py                       → М7. Метрики
│   └── comms.py, dsn.py, data/dsn_*.json → М8. Зв'язок і DSN
└── static/js/
    ├── state.js        → М9.  Спільний стан
    ├── calendar.js     → М10. Календар
    ├── overlay.js      → М11. Оверлей метрик
    ├── moon_globe.js   → М12. Глобус Місяця
    ├── system_view.js  → М13. 3D-вид системи
    ├── compare.js      → М14. Порівняння місць (ще не створено)
    └── three/          → М16. 3D-підсистема (спільна для М12 і М13)
tools/                  → М15. Передрозрахунки
tests/                  → тести для всіх модулів
```

Залежності: `М5 Ефемериди` + `М6 Радіогоризонт` → `М7 Метрики` → `М3 API` → `М11 Оверлей`, `М14 Порівняння`.
3D: `М16 3D-підсистема` → `М12 Глобус Місяця`, `М13 3D-вид системи`.
**Критичний шлях MVP — М5 Ефемериди:** поки він не готовий, API метрик повертає 501.

## М3. JSON API — 🟨
**Файли:** `app/routes/api.py`
**Призначення:** єдина точка доступу фронтенду до даних і розрахунків.

| Метод | Шлях | Параметри | Відповідь |
|---|---|---|---|
| GET | `/api/health` | — | `{"status": "ok"}` |
| GET | `/api/sites` | — | список місць (М4) |
| GET | `/api/sites/<id>` | — | одне місце або 404 |
| GET | `/api/dsn` | — | станції DSN (М8) |
| GET | `/api/metrics` | `lat`, `lon`, `datetime` (ISO 8601, UTC за замовчуванням) | метрики точки (М7) |
| GET | `/api/compare` | `site` ×2+, `datetime` | метрики кількох місць |

**MVP:**
- Валідація: `lat` ∈ [−90, 90], `lon` ∈ [−180, 360], дата у форматі ISO 8601. Помилка → 400 з JSON `{"error", "detail"}`.
- Нереалізований розрахунок → 501 з поясненням (фронтенд показує його в оверлеї).
- Усі відповіді — JSON; тексти помилок українською.

**Друга черга:** `/api/ephemeris` (положення тіл для 3D-сцени), `/api/search` (підбір локацій), `/api/launch-window`, `/api/timeline` (часові ряди для графіків).

**Пропозиції:**

## М5. Ефемериди — ⬜ (критичний шлях)
**Файли:** `app/services/ephemeris.py`, `tools/download_kernels.py`
**Призначення:** азимут, кут місця та відстань Сонця й Землі з точки на Місяці.

**Інтерфейс:**
- `sun_position(lat, lon, when) -> SkyPosition`
- `earth_position(lat, lon, when) -> SkyPosition`
- `next_crossing(lat, lon, when, body, rising) -> datetime | None`

**MVP:**
- Реалізація на **skyfield** + ефемериди DE440s (або DE421) + PCK орієнтації Місяця (`moon_pa_de440`, система `MOON_ME`).
- Точність кута місця — не гірше 0,1°.
- Діапазон дат — щонайменше 2026–2060 (десятки років уперед).
- Ядра SPICE завантажуються скриптом у `data_cache/`, у git не потрапляють.
- Звірка з JPL Horizons для 3–5 контрольних точок → тест.
- Пошук сходу/заходу з урахуванням маски горизонту (М6), крок пошуку ≤ 10 хв + уточнення бісекцією.

**Друга черга:** лібрація як окрема метрика, кешування результатів.

**Пропозиції:**
- …

## М6. Радіогоризонт — 🟨
**Файли:** `app/services/horizon.py`, `tools/build_horizon_masks.py`

**MVP:**

- Маски для місць із каталогу (М4) — передрозрахунок із DEM LOLA 20 м/піксель (`tools/`).

**Друга черга:** маски для довільних точок на льоту, сітки для підбору локацій.

## М16. 3D-підсистема — 🟨
**Файли:** `app/static/js/three/` (`scene.js`, далі — `textures.js`, `coords.js`, `picking.js`), importmap Three.js у `base.html`
**Призначення:** спільна основа для всіх 3D-сцен; М12 і М13 лише описують свій вміст.

**Інтерфейс (пропозиція):**
- `createScene(host, options) -> { scene, camera, renderer, controls, dispose }` — сцена в контейнері, ресайз, цикл рендерингу.
- `latLonToVector3(lat, lon, radius)` / `vector3ToLatLon(v)` — перетворення координат.
- `loadTexture(name, quality)` — текстури з кількома рівнями якості, кеш.
- `pick(scene, camera, event, targets)` — вибір точки кліком.
- `setSunDirection(scene, vector)` — освітлення за положенням Сонця з API.

**MVP:**
- Three.js підключається через importmap із закріпленою версією (без збирача).
- Керування мишею й дотиком (OrbitControls), ресайз під контейнер.
- Перевірка WebGL: без нього — 2D-заглушка й повідомлення, решта сторінки працює.
- Перемикач якості «низька / висока»; за замовчуванням — низька (текстура 2K).
- `dispose()` звільняє ресурси при зміні вкладки чи режиму.
- 60 к/с на середньому ноутбуці в режимі «низька».

**Друга черга:**
- рельєф південного полюса з DEM LOLA (displacement або тайли);
- вид «з поверхні»: панорама горизонту з маскою рельєфу, рух Сонця й Землі;
- тіні від рельєфу, межа дня й ночі в реальному часі;
- моделі апаратів (NASA 3D Resources);
- оцінка переходу на CesiumJS для глобуса.
