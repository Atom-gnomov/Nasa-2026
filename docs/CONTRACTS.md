# Контракти: API, дані, фронтенд

Контракт — домовленість про формат, яку бекенд, фронтенд і адаптери даних виконують незалежно один від одного. Поки контракт не змінюється, кожна сторона може працювати окремо: фронтенд — на прикладах, бекенд — на тестах, а нові дані (з'являться в п'ятницю) підключаються адаптером без змін у математиці й API.

| Що | Де | Для кого |
|---|---|---|
| Специфікація API (машиночитна) | [`contracts/openapi.yaml`](../contracts/openapi.yaml) (OpenAPI 3.1) | бекенд, фронтенд, генератори клієнтів |
| Приклади відповідей (моки) | [`contracts/examples.json`](../contracts/examples.json) | фронтенд до появи реалізації |
| Схеми файлів даних | [`contracts/schemas/*.schema.json`](../contracts/schemas/) (JSON Schema 2020-12) | дані в `app/data/`, `data_cache/` |
| Інтерфейси джерел даних | [`app/core/sources.py`](../app/core/sources.py) | адаптери нових наборів даних |
| Контрактні тести | [`tests/test_contracts.py`](../tests/test_contracts.py) | усі: тест падає, якщо код розійшовся з контрактом |

Математика, на якій стоять поля контракту, — [MATH.md](MATH.md). Модулі — [MODULES.md](MODULES.md).

## 1. Загальні домовленості

### 1.1. Одиниці — у назві поля
| Суфікс | Одиниця | Приклад |
|---|---|---|
| `_deg` | градуси | `sun_elevation_deg` |
| `_km`, `_m` | кілометри, метри | `earth_distance_km`, `height_m` |
| `_s`, `_h` | секунди, **земні** години | `signal_delay_s`, `hours_to_sunset` |
| `_fraction` | частка 0…1 | `sun_visible_fraction` |
| `_pct` | відсотки 0…100 | `score_pct` |
| `_w`, `_wh_per_m2`, `_k` | Вт, Вт·год/м², кельвіни | `energy_wh_per_m2` |

Ключі — `snake_case`. Без суфікса одиниць додаються лише безрозмірні або очевидні поля (`lat`, `lon`, `id`).

### 1.2. Час
- Вхід: ISO 8601. Рядок без часової зони вважається **UTC**. Без параметра `datetime` — поточний момент.
- Вихід: завжди UTC із `Z`, без мілісекунд: `2027-07-01T00:00:00Z`. Дата без часу — `2027-07-02`.

### 1.3. Координати
- **Місяць:** селенографічні координати в системі **MOON_ME**, опорна сфера R = 1737,4 км. Широта: південь — від'ємна. Довгота на схід; на вході приймається −180…360, на виході нормалізується до **[−180, 180)**.
- **Земля:** WGS84, геодезичні широта й довгота, висота над еліпсоїдом.
- **Азимут:** від півночі за годинниковою стрілкою, 0…360. **На самому полюсі** «північ» — напрямок на меридіан переданої довготи (grid north, MATH.md §5). Інтерфейс має це підписувати.
- **Кут місця:** від математичного горизонту (дотичної площини), без рельєфу. Рельєф враховується окремо — через маску горизонту й поля `*_visible*`.

### 1.4. `null` і відсутні значення
- `null` у `hours_to_*` — події немає в межах `event_search_hours` (наприклад, полярний день). Фронтенд показує «> {event_search_hours} год», а не «—».
- `recommended_station: null` — прямого зв'язку зараз немає.
- Поле присутнє завжди, навіть якщо значення `null`: фронтенд не перевіряє наявність ключа.

### 1.5. Помилки
Усі помилки `/api/*` — JSON одного формату:

```json
{"error": "bad_request", "detail": "Параметр lat має бути в межах [-90, 90]"}
```

| HTTP | `error` | Коли | Що робить фронтенд |
|---|---|---|---|
| 400 | `bad_request` | невірні параметри | підсвічує поле, показує `detail` |
| 404 | `not_found` | немає місця / невідомий шлях | показує `detail` |
| 501 | `not_implemented` | операція з контракту ще не реалізована | показує заглушку «у розробці»; може брати мок з `examples.json` |
| 503 | `unavailable` | на сервері немає потрібних даних (ефемериди, DEM) або не налаштована LLM для `/advice` | показує `detail`, пропонує спробувати пізніше |
| 500 | `internal` | помилка сервера | «Щось пішло не так» |

`detail` — українською, для показу користувачу як є.

### 1.6. Версії та сумісність
- Поточна версія контракту — **1.0.0** (`info.version` в `openapi.yaml`).
- **Сумісні зміни** (мінорна версія): нове поле у відповіді, новий необов'язковий параметр, нова операція. Фронтенд **ігнорує невідомі поля**.
- **Несумісні зміни** (мажорна версія): перейменування або видалення поля, зміна одиниць чи значення поля. Вони дозволені лише з новою версією й узгодженням із фронтендом; старий шлях живе до переходу.
- Статус операції — `x-status`: `implemented` або `planned`. Заплановані операції вже є на сервері й відповідають 501, тому фронтенд може писати код одразу.

### 1.7. HTTP
- Сайт і API — з одного домену, CORS не потрібен. Якщо фронтенд колись переїде окремо — додати CORS лише для його домену.
- Каталоги (`/sites`, `/dsn`, `/launch-sites`) змінюються рідко — фронтенд кешує їх на сесію.
- `/metrics` для одного моменту відповідає за десятки мілісекунд; `/timeline` і `/search` можуть бути довшими, тож фронтенд показує індикатор завантаження.

### 2.0. `POST /advice` — особливості
- LLM **лише інтерпретує** числа з `facts`; вона нічого не рахує. Поле `verified` у відповіді: `true`, якщо всі числа знайдено у `facts`; інакше фронтенд показує попередження «неперевірена порада».
- Порада завжди показується **окремо й підписана** «Порада ШІ — не розрахунок», з `model` і `generated_utc`.
- Якщо LLM не налаштована (`LSE_LLM_BASE_URL` порожня) — `503 unavailable`; фронтенд тоді не показує блок порад.
- Виклик до LLM іде лише з бекенду; у модель не передаються персональні дані.
- Контракт запиту `facts` навмисно вільний (довільні ключі): структура результатів місії з'явиться разом із `/mission` (задача B9 у `TASKS.md`).

## 4. Майбутні дані (стануть відомі в п'ятницю)

Ми ще не знаємо, які саме набори дасть організатор. Тому математика й API залежать не від файлів, а від **протоколів** у `app/core/sources.py`. Новий набір підключається адаптером.

### 4.1. Протоколи джерел
| Протокол | Контракт | Хто споживає |
|---|---|---|
| `HeightSource(lat, lon) → м` | висота відносно сфери 1737,4 км, MOON_ME, NaN поза покриттям | `core/horizon.compute_mask`, побудова масок; ✅ реалізовано `core/dem.py` (PDS LOLA, `moon`) |
| `MaskStore.get/put` | маска за схемою `horizon_mask.schema.json` | `services/horizon.load_mask` |
| `IlluminationSource.sun_fraction(lat, lon)` | частка часу 0…1 | швидкий фільтр підбору, валідація |
| `CatalogSource.records()` | записи за схемами каталогів | каталоги місць, станцій, стартів |

Ефемериди вже мають свій контракт: будь-який `.bsp` файл із тілами `sun`, `earth`, `moon` підключається змінною `LSE_EPHEMERIS_PATH`.

### 4.2. Порядок підключення набору даних
1. Покласти файли в `data_cache/<dataset_id>/` (у git не потрапляють).
2. Створити `manifest.json` за схемою `contracts/schemas/dataset_manifest.schema.json`: джерело, ліцензія, система координат, опорний радіус, одиниці висот, покриття.
3. Написати адаптер `app/adapters/<dataset_id>.py`, що реалізує потрібний протокол і **перетворює одиниці й систему координат на наші** (§1.3).
4. Додати тест адаптера: 2–3 відомі точки → очікувані значення та одиниці.
5. Додати набір у відповідь `/meta` (`data_sources`).

### 4.3. Що, ймовірно, дадуть і куди це піде
| Імовірний набір | Протокол | На що звернути увагу |
|---|---|---|
| DEM LOLA (GeoTIFF, полярна стереографічна) | `HeightSource` | ✅ (`moon`): підключено PDS GDR — LDEM_16/64 (V3.1), LDEM_80S_80M, LDEM_875S_20M (V2.0); параметри — з міток .LBL, формули — `dsmap*.cat` |
| Карти освітленості PGDA / Mazarico | `IlluminationSource` | період усереднення, висота над ґрунтом (часто 0 або 2 м) |
| Експорти JPL Horizons (таблиці) | тест-еталон для `core/ephemeris` | ✅ (`moon`): еталонні значення з API Horizons у `tests/test_contracts.py` |
| Список місць CLPS / Artemis | `CatalogSource` → `sites.json` | системи координат місць (ME чи PA), джерело |
| Координати DSN | `CatalogSource` → `dsn_stations.json` | WGS84 чи ITRF, мінімальні кути антен |
| Температури Diviner | ✅ (`moon`) `services/temperature.py` | GCP 0,5° за місцевим часом, PRP 0,5 км; сезони в GCP не розділено |

Якщо набір не вкладається в жоден протокол — додати новий протокол у `sources.py` і описати його тут, **не змінюючи** існуючих полів API.

## 5. Взаємодія з фронтендом

### 5.1. Спільний стан (`app/static/js/state.js`)
```js
{
  datetime: "2027-07-01T00:00Z",  // UTC
  site: "Apollo 11 (Море Спокою)" | null,  // підпис вибраного місця
  lat: -89.5 | null,
  lon: 0 | null,
  // заплановано: height_m, mode ("earth-moon" | "sun-moon-earth"), compare: [id, id]
}
```
- Синхронізується між вкладками через `localStorage` і параметри URL: `?datetime=&lat=&lon=&site=` (заплановано також `&height=&mode=&compare=`). Посиланням можна поділитися.
- Модулі змінюють стан лише через `setState()` і реагують через `subscribe()`.

### 5.2. Хто, коли й що запитує
| Модуль фронтенду | Запит | Коли |
|---|---|---|
| М11 Оверлей | `GET /metrics`, `/elevation`, `/horizon`, `/temperature`, `/timeline` (місячна доба від дати) — паралельно | зміна місця, дати чи висоти; затримка (debounce) 200 мс |
| М12 Глобус | `GET /sites` один раз; `GET /system` для освітлення; `/elevation`, `/temperature` під курсором; `/temperature/map` для шару | старт сторінки; зміна дати чи шару; рух курсора (120 мс) |
| М13 3D-вид | `GET /system?datetime`, `GET /orbits?datetime`, `GET /dsn` | зміна дати; під час анімації `/system` — до ~14 разів/с, `/orbits` — коли час зсунувся на 12 год |
| М14 Порівняння | `GET /compare?site&site&datetime` | зміна набору місць або дати |
| Графіки / таймлайн | `GET /timeline`, `GET /events` | зміна місця або діапазону дат |
| Підбір | `POST /search` | кнопка «Знайти» (не на кожен рух повзунка) |

Попередній незавершений запит при новому скасовується (`AbortController`), щоб старі відповіді не перезаписували нові.

### 5.3. Показ значень
- Кути — 2 знаки після коми, години — 1 знак, затримка — 3 знаки, частки — у відсотках без знаків.
- Азимут на полюсі підписувати: «від меридіана 0°».
- `true/false` → «так/ні»; кольори: видно — зелений, не видно — червоний.
- Тексти помилок — з `detail`, без змін.

### 5.4. 3D: як використовувати `SystemState`
- `sun_km`, `moon_km` — геоцентричні ICRF, км. Масштаб сцени задає фронтенд (схематичний або реальний).
- `moon_orientation` — матриця ICRF → MOON_ME. Щоб повернути модель Місяця, застосувати до неї **транспоновану** матрицю (MOON_ME → ICRF).
- Осі: MOON_ME `(x, y, z)` → Three.js `(x, z, −y)` — так само, як у `latLonToVector3` (`app/static/js/three/scene.js`): Y угору, на північний полюс.
- `sub_solar_point`, `sub_earth_point` — для швидкої перевірки: ці точки глобуса мають бути спрямовані на Сонце й на Землю.
- `earth_rotation_deg` (GAST) — поворот текстури Землі навколо її осі.
- `earth_orientation` — матриця ICRF → ITRS (прецесія, нутація, зоряний час). Модель Землі повертати транспонованою, як і Місяць.
- 3D-вид системи (`system_view.js`) додатково переводить ICRF в екліптику J2000 (нахил 23,4392911°), тоді вже (x, z, −y): орбіта Землі горизонтальна, вісь Землі нахилена. Освітлення кожного тіла — справжнім напрямком на Сонце з `sun_km`/`moon_km`.

### 5.5. Моки
Поки операція в статусі 📝, фронтенд бере приклад з `contracts/examples.json` (ключ — назва схеми). `Timeline` і `SystemState` у прикладах розраховані нашим ядром (89,5° пд. ш., 2027-07-01), решта прикладів — ілюстративні значення. Усі приклади проходять схеми — це перевіряє `tests/test_contracts.py`.

## 6. Як змінювати контракт
1. Спершу змінити `contracts/openapi.yaml` або схему, потім код — в одному PR.
2. Сумісна зміна → підняти мінорну версію; несумісна → мажорну й узгодити з фронтендом.
3. Оновити приклади в `contracts/examples.json` і цей документ.
4. `python -m pytest` — контрактні тести мають пройти.
