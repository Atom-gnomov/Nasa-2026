# Задачі та порядок реалізації

Робота розбита на дрібні задачі (кожна — один PR на 0,5–1 день) і згрупована у **хвилі**. Задачі однієї хвилі не залежать одна від одної й не змінюють ті самі файли, тому їх можна робити **паралельно від 2 до 6 агентів**.

Пов'язані документи: вимоги — [MODULES.md](MODULES.md), формули — [MATH.md](MATH.md), формати — [CONTRACTS.md](CONTRACTS.md).

## Як працювати із задачами
> **Актуальна версія цього файлу — у гілці `coordination`** (див. [BOARD.md](BOARD.md), «Гілка coordination»). Статуси й заявки змінюються лише там.

1. **Перевірити, що задача вільна:** `python tools/agents/status.py --check <ID>` — дивиться дошку [BOARD.md](BOARD.md) у `coordination`, гілки інших агентів і заявки в них.
2. **Заявити одразу — у `coordination`:** свій розділ у BOARD.md («Зараз: B3 — …») і статус 🔄 у таблиці нижче; одразу `git push origin coordination`.
3. **Гілка задачі від свіжого `main`:** `git fetch origin`, назва `<ім'я>/<ID>-<коротко>`, наприклад `veles/B3-timeline` (імена — BOARD.md). У гілці задачі `docs/` не змінювати.
4. Змінювати лише файли зі стовпця «Файли». Спільні файли (позначені *) — мінімальною точковою правкою. Файли з `docs/` у стовпці «Файли» змінюються в `coordination`.
5. **Підтягувати `main`** перед кожним push і після кожного злиття в `main` (AGENTS.md, «Постійно стежити за `main`»).
6. Готово, коли виконано критерії «Готово, коли», тести проходять, PR у `main` створено; у `coordination` — запис у своєму «Журналі» в BOARD.md і статус 👀. Злиття — лише Перун, після нього ✅.
7. Наступна хвиля починається, коли закриті задачі, від яких вона залежить; чекати всю попередню хвилю не обов'язково.

Статуси: ⬜ не розпочато · 🔄 у роботі · 👀 PR на рев'ю · ✅ злито · ⏸ чекає даних.
Розмір: **S** — до 2 год, **M** — пів дня, **L** — день.

## Доріжки (lanes) і розподіл між агентами

Кожна задача належить одній доріжці. Доріжки розділені за файлами, тому агенти на різних доріжках не конфліктують. Імена агентів — у [BOARD.md](BOARD.md).

| Доріжка | Зона файлів |
|---|---|
| **L1 Бекенд API** | `app/services/*.py`, `app/routes/api.py`*, `tests/test_api_*.py` |
| **L2 Математика й дані** | `app/core/*.py`, `app/adapters/`, `tools/`, `tests/test_core_*.py` |
| **L3 Фронтенд-оболонка** | `app/static/js/{state,calendar,overlay,compare,charts}.js`, `app/templates/`, `app/static/css/` |
| **L4 Фронтенд 3D** | `app/static/js/three/`, `moon_globe.js`, `system_view.js`, `app/static/textures/` |
| **L5 Інфраструктура** | `Dockerfile`, `compose.yaml`, `.github/workflows/`, `pyproject.toml` |
| **L6 Дані й документація** | `app/data/*.json`, `docs/`, `contracts/examples.json` |

| Агентів | Розподіл доріжок |
|---|---|
| 2 | **Перун:** L1 + L2 + L5 (бекенд) · **Велес:** L3 + L4 + L6 (фронтенд і дані) |
| 3 | **Перун:** L1 + L5 · **Велес:** L2 + L6 · **Ярило:** L3 + L4 |
| 4 | **Перун:** L1 · **Велес:** L2 + L6 · **Ярило:** L3 + L5 · **Сварог:** L4 |
| 5 | **Перун:** L1 · **Велес:** L2 · **Ярило:** L3 · **Сварог:** L4 · **Стрибог:** L5 + L6 |
| 6 | **Перун:** L1 · **Велес:** L2 · **Ярило:** L3 · **Сварог:** L4 · **Стрибог:** L5 · **Чорнобог:** L6 |

Розподіл — за замовчуванням; Перун може переназначити.

Коли доріжка агента в поточній хвилі порожня — він бере задачу з наступної хвилі своєї доріжки (якщо залежності закриті) або допомагає L6 (перевірка даних, документація).

## Конфлікт-контроль
- `app/routes/api.py` змінюють B2, B3, B4, B5, M1. Кожна задача лише замінює тіло **своєї** функції-заглушки на виклик сервісу (2–5 рядків), тому зміни зливаються без конфліктів.
- `base.html`, `style.css`, `state.js`, `scene.js` — спільні: одна задача — одна точкова правка; великі зміни — окремою задачею.
- Нова задача, якої немає в списку, — спершу рядок у цій таблиці (окремий PR або в тому самому PR першим комітом).
- Дошку BOARD.md кожен агент змінює лише у своєму розділі — правки різних агентів зливаються без конфліктів.
