# Передача реалізації повноекранного інтерфейсу

## Актуальна гілка й межі

Гілка реалізації — `yarylo/fullscreen-glass-ui`. **Не змінюйте `main` без дозволу власника.** Документація цього задуму — `design/` цієї гілки, бо спільні командні `docs/` знаходяться в гілці `coordination`.

Погоджений задум із розмірами й правилами — [fullscreen-workspace.md](fullscreen-workspace.md).
Три стани екрана — [layout-wireframes.svg](layout-wireframes.svg).

## Змінені файли та їхня роль

| Файл | Призначення |
|---|---|
| `app/templates/base.html` | Постійний хедер, нова навігація, дата, мова, fullscreen і підказки; підключення `workspace.css` і `workspace_ui.js` |
| `app/static/css/workspace.css` | Окремий шар стилів, який не переписує старий `style.css`; normal/collapsed/expanded; шапка; повноекранні сцени; аналітичні розкладки; адаптивність |
| `app/static/js/workspace_state.js` | Чиста модель переходів станів; без DOM; тести в Node |
| `app/static/js/workspace_ui.js` | Переносить **існуючі** DOM-вузли у віджети, не змінюючи їхні ID; додає collapse/expand, керування сценою і fullscreen; sessionStorage |
| `app/templates/moon.html` | Залишає глобус без вбудованого підбору; вибір та графіки зберігаються |
| `app/templates/search.html`, `app/routes/pages.py` | `GET /search` — самостійна аналітична сторінка |
| `app/templates/_search.html` | Оновлений текст про перехід результатів на глобус |
| `app/static/js/search.js`, `app/static/js/highlights.js` | Підбір переходить на `/moon` з вибраною точкою; координати результатів зберігаються у sessionStorage |
| `app/static/js/i18n/en.json` | Переклади доданих інструментів |
| `tests/js/test_workspace_ui.mjs` | Перевірка станів віджетів та їхньої взаємної виключності |
| `tests/test_pages.py`, `tests/test_search_js.py`, `tests/js/test_highlights.mjs` | Перевірки нової вкладки та міжсторінкових маркерів |

## Реальний шлях 3D-сцени при розгортанні

CSS використовує змінні `--scene-left` / `--scene-right` на body. Для `data-expanded="left"` вони стають відповідно `50vw` / `0px`; для `right` — навпаки. `#moon-globe`, `#system-view`, `#surface` і `.ui-dock` використовують ці змінні. Тому простір сцени фізично звужується й Three.js отримує зміну розміру контейнера через свій `ResizeObserver`. Не реалізовуйте цей стан простим великим overlay поверх старого canvas — це порушить вимогу.

Стан `{left,right}` нормалізується у `normalizeWidgetStates`, а команда `widgetTransition(state, side, action)` забезпечує автоматичне згортання протилежного віджета. Стан зберігається в `sessionStorage` у ключі `lse-ui-widgets:<page>`. Користувач не може перетягувати панелі.

У `normal` карта зберігає повну ширину за прозорими панелями. У `collapsed` лишається крайовий перемикач. У `expanded` відкритий віджет займає ліву або праву половину робочого простору, і тільки один може бути таким одночасно. Повторне натискання expand повертає `normal`, інший віджет не відкривається автоматично.

## Не переписуйте код розрахунків

`globe_view.js`, `surface_view.js`, `system_view.js`, `charts.js`, `compare.js`, `overlay.js`, `calendar.js`, `state.js` продовжують працювати з вихідними ID. Модуль `workspace_ui.js` **переміщує**, а не копіює елементи; не створюйте дубльовані вузли з тими самими ID.

Вкладка `/search` без карти; `#s-advice` переміщується з центру в праву колонку до запуску `search.js`. Перехід із результату до `/moon` зберігає координати в `state.js`, а кольорові маркери в `highlights.js` — через `sessionStorage` (лише в цій браузерній сесії, не у спільному URL).

У режимі «Вид з поверхні» `#surface` стає центральним полотном, а нижні три ряди його власних інструментів зберігаються. Кнопка «← Глобус» у верхній частині потрібна, бо док глобуса в цьому режимі прихований.

## Ручна перевірка у браузері

1. Запустити `flask --app app run --debug` із залежностями/даними проєкту.
2. Відкрити `/moon`: хедер нерухомий, глобус від краю до краю під ним, панелі ліворуч і праворуч прозорі, нижній док працює.
3. Згорнути/відкрити кожну панель; розгорнути ліву: права згорнута, реальна ширина `#moon-globe` ≈ половина робочого viewport. Розгорнути праву: ліву згорнуто, сцена переноситься ліворуч. Перевірити натискання та keyboard focus.
4. Обрати місце кліком на глобусі й через координати, перевірити оновлення метрик, графіків та курсора. Перевірити режими «Куля/Карта/Південний полюс».
5. Перейти на «Вид з поверхні» і назад «← Глобус»; перевірити перемикання 3D/Панорама/Розгортка, час і тіні.
6. Відкрити `/system`: глобальна 3D-сцена, ліворуч вибір фокуса й польоту, справа стан системи/телеметрія/додаткові метрики, знизу режим/масштаб/симуляція. Повторити 50/50.
7. Відкрити `/search`: без карти, 3 колонки, справа ШІ. Запустити пошук, натиснути результат — відкриється `/moon` з вибраною точкою та кольоровими маркерами.
8. Відкрити `/mission`, `/launch-window`, `/plan`: ліворуч форма, центр — результати, без карти. Перевірити рідні розрахунки.
9. Перевірити UA/EN, кроки дати, Fullscreen, підказки; ширини 1920, 1366, 1024, 768 і 390 px; повернення після перезавантаження збереженого стану віджетів.

## Перевірки в терміналі

```bash
python -m pytest tests/test_pages.py tests/test_i18n.py tests/test_search_js.py
node --test tests/js/test_workspace_ui.mjs tests/js/test_highlights.mjs tests/js/test_search.mjs
python -m pytest
```

У поточному середовищі роботи з репозиторієм через GitHub-конектор не запускається браузерний сервер; синтаксис доданих JS-файлів і чисті переходи станів перевірено, але **повний набір тестів та браузерні проходи залишаються завданням наступного виконавця**. Не заявляйте готовність до merge без перевірок CI та візуального QA.

## Подальші покращення після базового перенесення

- На мобільному екрані expanded панель займає весь робочий простір — логічно для малих viewport. Можна вдосконалити висувні панелі й швидке перемикання вкладок.
- Вирівняти багаторядкову нижню панель для 13–14″ ноутбуків; за потреби згрупувати рідко використовувані налаштування у `details`.
- Перенести повну локалізацію динамічних підказок до спільних функцій i18n, якщо словникових рядків стане недостатньо.
- Додати наскрізні browser тести відкриття/згортання/розгортання з перевіркою реального `getBoundingClientRect()` canvas.
- Перевірити пріоритети кліків для компасу/маркерів на картах, особливо коли лівий чи правий віджет розгорнуті.
