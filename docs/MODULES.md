# Вимоги до модулів

Документ описує модулі застосунку: за що кожен відповідає, які файли до нього належать, що він приймає й повертає, що потрібно для MVP і що відкладено на другу чергу.
Загальні вимоги — у [VISION.md](VISION.md), джерела даних — у [RESOURCES.md](RESOURCES.md).

**Стек:** Python 3.11+, Flask 3, Jinja2-шаблони, ванільний JavaScript (ES-модулі), Three.js для 3D.
**Запуск:** див. [README.md](../README.md).

Статуси: ⬜ не розпочато · 🟨 каркас / заглушка · ✅ готово для MVP.

У кожного модуля є підрозділ «Пропозиції» — туди дописуємо ідеї та покращення (коротко, з підписом). Великі пропозиції — у [PROPOSALS.md](PROPOSALS.md).

## Карта модулів

```
app/
├── __init__.py, config.py      → М1. Ядро застосунку
├── routes/pages.py, templates/ → М2. Сторінки (вкладки)
├── routes/api.py               → М3. JSON API
├── core/                       → М0. Математичне ядро (чисті функції, без Flask)
├── services/
│   ├── sites.py, data/sites.json        → М4. Каталог місць
│   ├── ephemeris.py                     → М5. Ефемериди
│   ├── horizon.py                       → М6. Радіогоризонт
│   ├── elevation.py                     → М6. Висота, нахил і експозиція (DEM LOLA)
│   ├── metrics.py                       → М7. Метрики
│   ├── timeline.py                      → М7. Ряди й підсумки за період, маска горизонту
│   ├── system.py                        → М13. Стан системи й орбіти
│   ├── temperature.py                   → М18. Температура (LRO Diviner)
│   └── dsn.py, data/dsn_*.json          → М8. Зв'язок і DSN
└── static/js/
    ├── state.js        → М9.  Спільний стан
    ├── calendar.js     → М10. Календар
    ├── overlay.js      → М11. Оверлей метрик
    ├── moon_globe.js, globe_view.js → М12. Глобус Місяця
    ├── system_view.js  → М13. 3D-вид системи
    ├── compare.js      → М14. Порівняння місць (ще не створено)
    └── three/          → М16. 3D-підсистема (спільна для М12 і М13)
tools/                  → М15. Передрозрахунки
Dockerfile, compose.yaml → М17. Docker (ще не створено)
tests/                  → тести для всіх модулів
```

Залежності: `М0 Ядро` → `М5 Ефемериди` + `М6 Радіогоризонт` → `М7 Метрики` → `М3 API` → `М11 Оверлей`, `М14 Порівняння`.
3D: `М16 3D-підсистема` → `М12 Глобус Місяця`, `М13 3D-вид системи`.
**М6 закрито (PR #12):** маска горизонту рахується на льоту з DEM LOLA (20/80 м біля південного полюса, далі — глобальний). Наступне на критичному шляху — М14 Порівняння.

**Файли:** `app/core/*.py`, тести `tests/test_core_*.py`, `tests/test_ephemeris.py`
**Призначення:** уся математика проєкту в одному місці. Чисті функції на numpy, без Flask — їх можна викликати зі скриптів `tools/`, сервісів і тестів. Формули — [MATH.md](MATH.md).

**MVP:**
- `getState()`, `setState(patch)`, `subscribe(fn)`.
- Синхронізація між вкладками через `localStorage` і параметри URL (`?datetime=&site=&lat=&lon=&height=&mode=&compare=`), щоб посиланням можна було поділитися; URL оновлюється без перезавантаження (`history.replaceState`), посилання — повний знімок стану (CONTRACTS.md §5.1; F1, PR #15).
- Стан із посилання одразу зберігається в `localStorage` (F12, PR #16); `datetime` з URL нормалізується до UTC `YYYY-MM-DDTHH:mmZ` (F13, PR #17).
- Некоректні значення з URL відкидаються; помилки доступу до `localStorage` (приватний режим) і обмеження частоти `replaceState` не ламають сторінку.
- Тести: `tests/js/test_state.mjs` (`node --test`), обгортка `tests/test_state_js.py`.

**Пропозиції:**
- `system_view.js` пише режим у `mode` через `setState()` (зараз режим живе лише в шляху `/system/<mode>`).
- Слухач події `storage` — живе оновлення стану у вже відкритих вкладках.

## М17. Docker і розгортання — ⬜ (на майбутнє)
**Файли (створити):** `Dockerfile`, `compose.yaml`, `.dockerignore`, розділ у `README.md`
**Призначення:** запуск застосунку однією командою на будь-якій машині (ноутбук команди, сервер для демо, хмара).

**Вимоги:**
- `docker compose up` збирає й запускає сайт на http://localhost:5000; більше нічого встановлювати не потрібно.
- Базовий образ — офіційний `python:3.13-slim` (з закріпленою версією); залежності з `requirements.txt` встановлюються окремим шаром, щоб зміни коду не перевстановлювали бібліотеки.
- Вебсервер у контейнері — **gunicorn**, а не `flask run` (той лише для розробки).
- Ефемериди DE440 (~114 МБ) — усередині образу: застосунок працює без доступу до інтернету.
- Великі дані (DEM LOLA, маски горизонту, `data_cache/`) — у **томі** (volume), шлях задається `LSE_CACHE_DIR`; образ не роздувається, дані не губляться при перезбиранні.
- Налаштування — лише через змінні середовища (`SECRET_KEY`, `LSE_CACHE_DIR`, `LSE_EPHEMERIS_PATH`, порт); секрети не потрапляють в образ і git.
- Контейнер працює не від root; є `HEALTHCHECK` на `/api/health`.
- Скрипти передрозрахунків (`tools/`) запускаються в тому самому образі: `docker compose run --rm app python tools/...`.
- Тести в контейнері: `docker compose run --rm app python -m pytest`.

**Друга черга:**
- збирання образу й прогін тестів у CI (GitHub Actions) на кожен PR;
- публікація образу в GitHub Container Registry;
- окремий сервіс для передрозрахунків, якщо вони стануть довгими.
